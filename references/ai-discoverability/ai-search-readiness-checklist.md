# AI 搜索可发现性准备度清单

> 这是方案和证据模板，不是网站执行清单。插件只生成判断、优先级、任务分工和验证方式，不访问网站、不修改代码、不提交平台。

## 0. 业务与目标

| 字段 | 需要记录 |
| --- | --- |
| 业务类型 | 电商 / SaaS / B2B / 内容 / 本地服务 / 其他 |
| 目标用户 | ICP、购买角色、使用角色、主要场景 |
| 目标结果 | 产品发现 / 合格访问 / 注册 / 激活 / 购买 / 收入 |
| 重点页面 | 首页、产品页、定价页、对比页、案例页、帮助页或内容页 |
| 当前证据 | 站点快照、Search Console、Analytics、Feed、结构化数据测试、工程说明 |

## 1. 可抓取与可索引

- [ ] 生产页面、规范 URL、`noindex`、robots 和 sitemap 的状态有证据；
- [ ] 关键事实可以在原始 HTML 或稳定渲染结果中获得；
- [ ] 测试环境和重复 URL 不会污染索引；
- [ ] 页面性能、移动端体验和关键资源阻塞有检查结果；
- [ ] 产品、服务或组织页面的主要信息不会只依赖不可用的客户端脚本。

状态只能填：`ready` / `partial` / `missing` / `needs-external-validation` / `not-applicable`。

## 2. 机器可理解的信息

按业务类型选择，不要为了覆盖清单而添加无关 Schema：

- [ ] Organization / LocalBusiness：名称、官网、标识、联系方式和业务关系一致；
- [ ] Product / ProductGroup：产品名、品牌、型号、变体、SKU / GTIN / MPN 等事实一致；
- [ ] Offer：价格、币种、库存、有效期、配送和退换货政策有来源；
- [ ] Review / AggregateRating：评价真实、范围正确、没有人为制造评分；
- [ ] Breadcrumb / ItemList / Article / HowTo / VideoObject：只有在页面类型真实匹配时使用；
- [ ] 结构化数据、页面可见内容和 Feed 之间没有冲突。

## 3. 内容可提取与可信度

- [ ] 页面开头能直接回答用户是谁、遇到什么问题、产品如何解决；
- [ ] 有清晰的目标用户和使用场景，而不是只堆砌关键词；
- [ ] 有真实差异化、限制条件、适用边界和对比信息；
- [ ] 关键页面包含 FAQ、摘要、要点或步骤，但不为了 AI 生成重复页面；
- [ ] 作者、专家、案例、引用、评价或一手数据能支持可信度；
- [ ] 内部链接把问题、方案、产品、案例和下一步动作连接起来；
- [ ] 语言、本地化、无障碍和图片替代文本符合实际用户需要。

## 4. 电商与 Feed（仅适用时）

- [ ] 商品 Feed、页面价格、库存、配送和退换货信息保持一致；
- [ ] 每个商品或变体有稳定且可理解的 URL / ID；
- [ ] Merchant Center 或其他官方平台的适用性、政策和监控责任已确认；
- [ ] 价格、促销、季节属性和库存变更有更新机制；
- [ ] 不把“提交到 LLM”当成通用动作，只记录有明确官方入口的平台事项。

## 5. 获客与商业结果

- [ ] 能区分自然搜索、AI / 推荐来源、目录来源和直接访问；
- [ ] 能追踪落地页访问、合格访问、注册、激活、购买或收入；
- [ ] 有主指标、护栏指标、观察窗口和停止条件；
- [ ] 不用排名、引用次数、抓取次数、外链数量或“被 AI 提及”单独证明增长；
- [ ] 后续结果可以接回 AARRR、Cohort 和 MRR 分析。

## 6. 优先级规则

1. P0：阻断抓取、索引、页面事实或交易信息准确性的事项；
2. P1：阻断用户理解、信任或完成首次价值行为的事项；
3. P2：可提升内容覆盖、比较效率或分群相关性的事项；
4. P3：仅在有明确证据和实验设计时处理的展示优化。

每项必须带负责人、来源、目标日期、验证方法和“不做什么”。
