# External acquisition resources

This resource pack brings a curated snapshot of external product-directory and discovery routes into `增长获客`. It is a methodology and execution-SOP resource pack, not a live submission agent.

Use it in this order:

1. Define the acquisition or referral outcome.
2. Filter candidates by product type, market, route and audience.
3. Write down the live-site, terms and current-submission-path checks that a later operator must complete.
4. Run the quality gate and remove paid-link, forced-reciprocal, irrelevant, unavailable or low-quality routes.
5. Use the record template to prepare site-level authorization and human-handoff steps; do not open a browser or perform a form action.
6. Audit the plan, then define how future verified referral visits, activation and conversion would connect back to AARRR.

The candidate list is a snapshot from the upstream project. Historical notes are context only; they are not current availability or submission status.

The `upstream/` folder preserves source reference material and attribution. It is not an instruction to invoke browser controls or perform live submissions; the local skill boundary above takes precedence.

## Choose a mode

| Mode | Use when | Control |
| --- | --- | --- |
| V2 Quality | Brand safety, relevance and durable referral value matter | Plan at most 10 sites; quality gate and site-level approval checklist |
| V1 Batch | The user already supplied a screened list and throughput matters | Normalize, deduplicate, shard and define checkpoints; do not run the batch |

## Record states

For plugin output, use `planned`, `ready for approval` and `not attempted`. If a user later supplies evidence from an external operator, the record can additionally use `submitted`, `awaiting approval`, `awaiting email verification`, `published`, `submission outcome unknown`, `submission failed`, `blocked — user action`, `blocked — missing verified data`, `ineligible` or `unavailable`.

`submission outcome unknown` is not a failure and is not permission to retry. The plugin does not check the account backend, mailbox or public page; the later operator must complete that verification first.

## Evidence and privacy

Keep the campaign record shareable and the controlled evidence store separate. Record opaque evidence IDs rather than passwords, OTPs, cookies, recovery codes, OAuth parameters, magic links, private emails, phone numbers or raw session identifiers.
