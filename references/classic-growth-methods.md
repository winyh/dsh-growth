# 经典增长方法论与落地 SOP

本文是 `growth-strategy-planning` 的统一方法参考。它把经典框架变成可使用的输入、输出、指标和下一步，不把方法名当成结论，也不执行外部动作。

## 统一使用顺序

```text
明确业务目标
→ 判断增长阶段和证据
→ 选择最小方法组合
→ 产出一页方案或决策材料
→ 绑定指标与护栏
→ 形成 HADI 实验
→ RICE / ICE 排序
→ WBR / MBR 复盘
```

每个方法必须回答：什么时候用、需要什么证据、产出什么、连接哪个指标、下一步怎么验证。

## P0：从问题到可执行增长方案

### 1. Value Proposition Canvas

**适用：** 用户说不清、产品卖点很多但价值不聚焦、不同分群使用同一套文案。

**输入：** 用户任务、痛点、期望收益、现有替代方案、产品能力、阻力和证据。

**输出：** 用户侧的 Jobs / Pains / Gains 与产品侧的 Products / Pain Relievers / Gain Creators 对照表，并标注已验证、假设和缺口。

**连接指标：** 激活率、首次价值时间、留存、转化率、付费率。

**SOP：** 先写用户任务，再写痛点和期望进步；最后才填产品能力。没有访谈、行为或购买证据的匹配只能标记为假设。

### 2. Lean Canvas

**适用：** 项目目标、客户、渠道、收入和成本分散在不同文档，团队对“增长问题”理解不一致。

**输入：** 问题、客户分群、独特价值主张、解决方案、渠道、收入、成本、关键指标和不公平优势。

**输出：** 一页业务假设地图，标出最高风险假设、证据来源和下一项验证。

**连接指标：** North Star、Acquisition、Activation、MRR、CAC、LTV。

**SOP：** 只保留当前决策需要的假设；每格最多写 1–3 条；给每条假设标注事实、估计或待验证，不把画布当成商业计划书。

### 3. Aha Moment / Activation Event

**适用：** 注册量增长但用户没有获得价值，团队无法统一定义“激活”。

**输入：** 用户事件、首次价值行为、时间窗口、分群、后续留存或付费结果。

**输出：** 激活事件定义、激活窗口、前置行为、护栏指标和待验证假设。

**连接指标：** Activation Rate、Time to Value、D7 / D30 Retention、Paid Conversion。

**SOP：** 不从“用户登录了什么”开始，而从“用户完成什么后更可能持续获得价值”开始；先观察相关性，再用实验验证，不把相关性当因果。

### 4. Churn Taxonomy / Win-back

**适用：** 只看到流失率，不知道流失原因、流失时点和召回策略。

**输入：** 流失时间、使用频率、套餐、支付、支持记录、取消原因、最后一次价值行为和召回结果。

**输出：** 流失分类、预警信号、可干预窗口、召回方案、停止条件和复购质量指标。

**连接指标：** Logo Churn、Revenue Churn、NRR、Resurrection、Win-back Rate、LTV。

**SOP：** 先区分自愿 / 非自愿流失、产品价值不足 / 价格 / 支持 / 竞争替代，再为每类选择动作；召回不能掩盖新用户激活和产品价值问题。

### 5. Bullseye Framework

**适用：** 渠道列表很长、团队同时尝试多个渠道、无法判断先做什么。

**输入：** ICP、渠道候选、到达方式、验证成本、预期质量、可扩展性、合规限制和历史证据。

**输出：** 三层渠道地图：候选层、验证层、重点层；每个渠道有最小测试、判断标准和停止条件。

**连接指标：** Qualified Acquisition、Activation、CAC、Payback、Referral Quality。

**SOP：** 先列可能渠道，再用小成本实验验证，再把已经证明有质量的渠道纳入重点；不要用流量或外链数量替代合格获客。

### 6. Opportunity Solution Tree

**适用：** 诊断之后马上跳到功能需求，团队没有比较不同解决方案的过程。

**输入：** 目标结果、用户机会、证据、解决方案候选、实验和限制条件。

**输出：** Outcome → Opportunities → Solutions → Experiments 的树，标出证据等级和当前分支。

**连接指标：** North Star、AARRR 瓶颈指标、HADI 主指标和护栏。

**SOP：** 先固定结果，再描述用户机会；至少保留两个解决方案分支；每个分支必须能转成实验，不直接把用户请求写成产品功能。

## P1：增强研究、循环和机会判断

### 7. The Mom Test / Switch Interview

**适用：** 用户访谈充满客套意见，团队不知道用户现在如何解决问题、为何切换或为何不买。

**输入：** 最近一次真实行为、现有替代方案、付出的时间和成本、触发事件、切换阻力。

**输出：** 访谈提纲、事实 / 观点编码、替代方案地图、切换证据和待验证问题。

**连接指标：** Activation、Conversion、Churn、Win-back、Pricing。

**SOP：** 少问“你会不会使用”，多问“上一次什么时候发生、怎么做、花了什么代价”；不把访谈意愿当购买证据。

### 8. Referral Loop / K-factor

**适用：** 推荐被当成一个漏斗阶段，但产品本身可能产生邀请、分享或网络效应。

**输入：** 触发场景、分享动作、受邀用户、接受率、激活率、邀请成本和质量护栏。

**输出：** 推荐循环图、循环输入 / 输出、K-factor 口径、反作弊规则和实验方案。

**连接指标：** Referral Rate、Invite Acceptance、Referred Activation、Retention、Revenue。

**SOP：** 先确认推荐对用户有真实价值，再设计触发和激励；不要把邀请数或分享数直接当成增长结果。

### 9. TAM / SAM / SOM

**适用：** 团队需要判断市场是否足够、分群是否值得投入或渠道规模是否被高估。

**输入：** 市场定义、客户数量、价格 / 支出、可服务地域、产品约束、来源和估计范围。

**输出：** 自上而下与自下而上的规模估算、假设表、敏感性分析和下一步验证。

**连接指标：** ICP、渠道容量、CAC、Pipeline、MRR 上限。

**SOP：** 先定义市场边界和购买单位，再写公式和来源；结果必须带区间和不确定性，不能把 TAM 当收入预测。

## P2：商业化与经营闭环

### 10. Pricing Research：Van Westendorp / Gabor-Granger

**适用：** 价格阻力不清、套餐设计没有证据、收入增长依赖无规则折扣。

**输入：** 目标分群、价值单元、价格区间、购买意愿、替代方案、毛利和实际支付行为。

**输出：** 价格敏感度假设、套餐 / 包装方案、实验设计和收入、转化、留存护栏。

**连接指标：** ARPA、Conversion、Expansion、Churn、NRR、Gross Margin、LTV。

**SOP：** 问卷结果只能作为意愿信号，必须和实际购买、升级、降级、流失行为结合；不把单次报价反馈当成最优价格。

### 11. B2B Revenue Funnel / MEDDICC

**适用：** AARRR 无法解释线索到成交的长周期、多角色和销售推进问题。

**输入：** Lead、MQL、SQL、Opportunity、决策者、痛点、预算、决策流程、竞争、阶段时间和成交结果。

**输出：** B2B 收入漏斗、阶段定义、转化率、停滞原因、销售质量和下一步动作。

**连接指标：** Pipeline、Win Rate、Sales Cycle、CAC、ACV、MRR、Expansion。

**SOP：** 先统一阶段进入 / 退出条件，再按账户和机会去重；MEDDICC 用于检查决策证据，不作为强行打分或替代真实销售判断。

### 12. Growth Accounting

**适用：** 活跃用户或收入变化看似增长，但团队无法拆出新增、留存、召回和扩张的贡献。

**输入：** 新增、留存、流失、召回、扩张、收缩、时间窗口和用户 / 客户粒度。

**输出：** 用户或收入增长桥、增长来源、负向贡献、分群差异和下一项验证。

**连接指标：** AARRR、Cohort、MRR Bridge、NRR、LTV。

**SOP：** 统一期初、期末和状态变化定义；任何无法闭合的桥都输出警告，不用零填补缺失变化。

### 13. OKR / A3 / OODA / Decision Log

**适用：** 目标、指标、实验和决策分散，复盘后无法知道下一步是否改变。

**输入：** 目标、现状、问题、证据、行动、负责人、截止日期、决策和复盘结果。

**输出：** 目标—指标—行动—决策日志，保留假设变更和未采用方案。

**连接指标：** North Star、WBR / MBR、HADI、RICE、经营结果。

**SOP：** OKR 负责方向，A3 负责问题叙事，OODA 负责快速迭代，Decision Log 负责记录决策；不要把四套格式叠加成新的汇报负担。

## 统一反模式

- 方法名称出现，不等于方法已经使用；必须有输入、证据和输出；
- 相关性不能直接写成因果；
- 访谈意愿、页面访问、分享次数、外链数量、排名或 AI 提及不能单独证明增长；
- 缺失数据必须标记为缺失或待验证，不得自动补零；
- 每次只选择能改变当前决策的最小方法组合。
